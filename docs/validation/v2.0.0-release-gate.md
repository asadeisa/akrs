# Validation — the v2.0.0 release gate

**What this is:** the evidence that the packaged AKRS v2 works end to end. Each gate names the test
files that prove it and the result. Every path below is a file in this repository, and
`test/phase2-gate/report.test.js` fails if one of them goes missing.

**How it is run:** `npm test` (the whole suite, Windows and Linux, Node 22.17.0 and 24.x in CI),
`npm pack --dry-run`, and `node --test test/package/pack-smoke.test.js`. The gate tests that need the
packaged product pack one tarball into a dedicated OS temp directory, install it into a clean
project and drive every loop from the installed copy in separate processes; they delete exactly
those paths afterwards and compare `git status --short` before and after.

### Owner dogfood record (AX gate item 8)

- **CLI arm, weak executor (Claude Haiku 4.5), 2026-10-22: passed.** The Worker finished the packaged
  example's Road in `work → done` and the Tester finished it in `test-details → test run → test result`.
  The model made no out-of-scope edit and, on a blocked contract, stopped instead of inventing a verdict.
  Ten findings (extra next commands, a stale State note, per-command help, a missing exact
  `test result` form, a duplicated boundary, a contract the writer accepted and the reader blocked,
  authoring friction) were fixed afterwards, each with a test; finding 7 (the Tester packet showing a
  declared check as having no recorded result) is only partly addressed: the packet now says that a
  Worker `done` runs the declared checks but does not store their outcome.
- **Frontier executor: waived** by the owner, on the strength of the weak executor's result.
- **MCP arm: not run.** It is deferred until after the v2.0.0 release by an explicit owner decision.
  It is **not** claimed as passed. What does pass is the automated MCP conformance and loop test run
  against the installed tarball, which is a required gate in CI.

## What was checked beyond the plan

- The pre-write guard, the offline board, the nine agent adapters and the MCP server are exercised
  from the installed package, not only from the checkout, because the checkout can hide a file that
  the `files` allow-list leaves out of the tarball.
- Gate tests that prove behaviour already built were green on their first run: they close holes
  between the packet suites rather than demand new behaviour.
